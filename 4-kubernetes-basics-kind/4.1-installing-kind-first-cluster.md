# 4.1 Installing kind and Creating Your First Cluster

## Concept Recap

`kind` (Kubernetes IN Docker) runs a real Kubernetes cluster using Docker containers as its 'nodes' - perfect for learning locally without cloud costs.

## Objective

Install kind and stand up your first local cluster.

## Prerequisites

- Module 3 complete
- Docker installed and running
- kind and kubectl installed
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Confirm tools are installed

```bash
kind version
kubectl version --client
```

### Step 2: Create your first cluster

```bash
kind create cluster --name learning
```

### Step 3: Confirm kubectl is pointed at it

```bash
kubectl cluster-info --context kind-learning
```

### Step 4: See the node(s)

```bash
kubectl get nodes
```

A default kind cluster has one node acting as BOTH control plane and worker - fine for learning, unrealistic for production.

## Check Your Understanding

**Q1: What does kind actually use to simulate Kubernetes nodes?**

<details><summary>Answer</summary>

Docker containers - each 'node' is really a container running the Kubernetes components.

</details>

**Q2: Is a default single-node kind cluster realistic for production?**

<details><summary>Answer</summary>

No - production clusters separate control-plane and worker nodes, and have multiple of each for redundancy. kind is for learning/testing.

</details>

**Q3: How do you point kubectl at a specific cluster if you have several?**

<details><summary>Answer</summary>

`kubectl config use-context <context-name>`, or `--context` on individual commands.

</details>

## Common Mistakes

- **Forgetting which cluster/context you're pointed at** - Always check `kubectl config current-context` if commands aren't behaving as expected - you may be targeting the wrong cluster.
- **Creating many kind clusters and forgetting to delete them** - Each one consumes real Docker resources - clean up with `kind delete cluster --name X` when done.

## Cleanup

```bash
kind delete cluster --name learning2 2>/dev/null || true
```
