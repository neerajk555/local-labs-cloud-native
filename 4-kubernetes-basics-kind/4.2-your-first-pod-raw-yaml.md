# 4.2 Your First Pod (Raw YAML)

## Concept Recap

You'll write raw Pod YAML once, deliberately, to understand the structure - even though in practice you'll almost always use Deployments (Lab 4.4) instead of bare Pods.

## Objective

Write, apply, and inspect a Pod from a YAML file.

## Prerequisites

- Lab 4.1 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Write the YAML

```bash
cat > pod.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: my-first-pod
spec:
  containers:
    - name: nginx
      image: nginx:1.27
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `pod.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `pod.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-first-pod
spec:
  containers:
    - name: nginx
      image: nginx:1.27
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

Compare this structure to a compose.yaml service - `image:` should look familiar.

### Step 2: Apply it

```bash
kubectl apply -f pod.yaml
```

### Step 3: Watch it come up

```bash
kubectl get pods -w
```

Press Ctrl+C once you see STATUS become Running.

### Step 4: Inspect it in detail

```bash
kubectl describe pod my-first-pod
```

### Step 5: See its logs

```bash
kubectl logs my-first-pod
```

## Check Your Understanding

**Q1: What command applies a YAML file to your cluster?**

<details><summary>Answer</summary>

`kubectl apply -f <filename>`.

</details>

**Q2: What's the equivalent of `docker logs` for a Pod?**

<details><summary>Answer</summary>

`kubectl logs <pod-name>`.

</details>

**Q3: If you delete this Pod directly, does anything recreate it?**

<details><summary>Answer</summary>

No - a bare Pod has no controller watching it. This is exactly why Deployments exist (Lab 4.4).

</details>

## Common Mistakes

- **Expecting a deleted bare Pod to come back on its own** - It won't - only Pods managed by a Deployment/ReplicaSet get automatically recreated.
- **Using tabs instead of spaces in YAML** - YAML is strict about indentation and does not allow tabs - use spaces consistently (2 is conventional).

## Cleanup

```bash
kubectl delete -f pod.yaml
```
