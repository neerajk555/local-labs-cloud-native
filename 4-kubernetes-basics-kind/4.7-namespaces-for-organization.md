# 4.7 Namespaces for Organization

## Concept Recap

A Namespace is a way to divide one cluster into logical sections - useful for separating teams, environments, or (as in the AWS labs' shared-cluster model) separate course participants.

## Objective

Create namespaces and see how they isolate resources with the same name.

## Prerequisites

- Lab 4.6 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Create two namespaces

```bash
kubectl create namespace team-a
kubectl create namespace team-b
```

### Step 2: Deploy the SAME-named app into both

```bash
kubectl create deployment web --image=nginx:1.27 -n team-a
kubectl create deployment web --image=nginx:1.27 -n team-b
```

Same Deployment name in two different namespaces - no conflict.

### Step 3: Confirm they're independent

```bash
kubectl get deployments -n team-a
kubectl get deployments -n team-b
kubectl delete deployment web -n team-a
kubectl get deployments -n team-b
```

Deleting in team-a doesn't affect team-b at all.

### Step 4: See ALL namespaces and set a default for your session

```bash
kubectl get namespaces
kubectl config set-context --current --namespace=team-b
kubectl get deployments
```

Now commands default to team-b without needing -n every time.


## Try It Yourself

**Exercise 1:** Try creating a SECOND deployment also named `web` in team-b (which already has one). What error do you get, and why?

<details><summary>Hint (try first without peeking)</summary>

You'll get an 'already exists' error - names must be unique WITHIN a namespace, but not across namespaces, exactly what you just demonstrated with team-a vs team-b.

</details>

## Check Your Understanding

**Q1: Do two objects with the same name in different namespaces conflict?**

<details><summary>Answer</summary>

No - names only need to be unique WITHIN a namespace.

</details>

**Q2: What command sets your kubectl session's default namespace so you don't need -n every time?**

<details><summary>Answer</summary>

`kubectl config set-context --current --namespace=<name>`.

</details>

**Q3: From the AWS labs' shared-cluster model, why did each participant get their own namespace?**

<details><summary>Answer</summary>

So 25 people could deploy identically-named resources (like `web`) without colliding, and so RBAC could restrict each person to only their own namespace.

</details>

## Common Mistakes

- **Forgetting to switch back your default namespace and being confused why resources 'disappeared'** - Check `kubectl config view --minify | grep namespace` if `kubectl get` shows unexpectedly empty results - you may be looking in the wrong namespace.
- **Assuming namespaces provide strong security isolation by themselves** - Namespaces organize resources, but real access control needs RBAC (Role-Based Access Control) on top, as seen in the AWS labs' Module 4.0 per-participant RBAC setup.

## Cleanup

```bash
kubectl delete namespace team-a team-b
kubectl config set-context --current --namespace=default
```
