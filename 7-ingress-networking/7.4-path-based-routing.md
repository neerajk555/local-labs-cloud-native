# 7.4 Path-Based Routing

## Concept Recap

Path-based routing sends traffic to different backends based on the URL PATH, all under the same hostname - e.g. example.com/api goes to one service, example.com/web goes to another.

## Objective

Route two different paths on the same host to two different backend Services.

## Prerequisites

- Lab 7.3 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Deploy two backends (reuse the pattern from 7.3)

```bash
kubectl create deployment app-a --image=hashicorp/http-echo -- -text='response from /a'
kubectl create deployment app-b --image=hashicorp/http-echo -- -text='response from /b'
kubectl expose deployment app-a --port=5678
kubectl expose deployment app-b --port=5678
```

### Step 2: Create a path-based Ingress

```bash
cat > ingress-path.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: path-based
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - http:
        paths:
          - path: /a
            pathType: Prefix
            backend:
              service:
                name: app-a
                port:
                  number: 5678
          - path: /b
            pathType: Prefix
            backend:
              service:
                name: app-b
                port:
                  number: 5678
EOF
kubectl apply -f ingress-path.yaml
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `ingress-path.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `ingress-path.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: path-based
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
    - http:
        paths:
          - path: /a
            pathType: Prefix
            backend:
              service:
                name: app-a
                port:
                  number: 5678
          - path: /b
            pathType: Prefix
            backend:
              service:
                name: app-b
                port:
                  number: 5678
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 3: Test both paths

```bash
curl http://localhost/a
curl http://localhost/b
```


## Try It Yourself

**Exercise 1:** Change app-a's path from `Prefix` to `Exact` and confirm `/a/anything` now 404s, whereas it worked with Prefix.

<details><summary>Hint (try first without peeking)</summary>

`pathType: Exact` only matches the literal path `/a`, not sub-paths - `Prefix` matches `/a` and anything starting with `/a/`.

</details>

## Check Your Understanding

**Q1: What's the difference between pathType: Prefix and pathType: Exact?**

<details><summary>Answer</summary>

Prefix matches the given path AND anything nested under it (like /a/anything); Exact matches ONLY that literal path.

</details>

**Q2: Can host-based and path-based routing be combined in one Ingress?**

<details><summary>Answer</summary>

Yes - you can nest multiple `paths` entries under a single `host` rule, combining both dimensions.

</details>

## Common Mistakes

- **Forgetting the rewrite-target annotation when the backend app expects requests at /** - Without it, the backend receives the full original path (e.g. /a) instead of / - some apps care about this, some don't; check your app's actual routing expectations.
- **Using Exact when you meant to match sub-paths too** - Exact is stricter than most people expect - use Prefix unless you specifically need to disallow sub-paths.

## Cleanup

```bash
kubectl delete -f ingress-path.yaml
kubectl delete deployment,service app-a app-b
rm -f ingress-path.yaml
```
