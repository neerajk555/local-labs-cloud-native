# 7.6 Intro to NetworkPolicy (Basic Pod-to-Pod Restriction)

## Concept Recap

By default, ANY Pod in a Kubernetes cluster can talk to ANY other Pod - there's no network isolation out of the box. A NetworkPolicy restricts this, similar in spirit to a firewall rule.

## Objective

Block Pod-to-Pod traffic by default, then selectively allow it back for one specific case.

## Prerequisites

- Lab 4.6 complete (labels/selectors)

## Steps

### Step 1: Confirm unrestricted access by default

```bash
kubectl create deployment web --image=nginx:1.27
kubectl expose deployment web --port=80
kubectl run tester --image=alpine --rm -it -- wget -qO- --timeout=3 http://web
```

This works - nothing is blocking Pod-to-Pod traffic by default.

### Step 2: Apply a default-deny policy for the web Pods

```bash
cat > deny-all.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-to-web
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
    - Ingress
EOF
kubectl apply -f deny-all.yaml
```

### Step 3: Confirm access is now blocked

```bash
kubectl run tester2 --image=alpine --rm -it -- wget -qO- --timeout=3 http://web
```

This should now time out - an empty `ingress:` list with no rules means DENY ALL incoming traffic to matching Pods.

### Step 4: Selectively allow traffic back, only from Pods labeled role=trusted

```bash
cat > allow-trusted.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-trusted-to-web
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              role: trusted
EOF
kubectl apply -f allow-trusted.yaml
kubectl run tester3 --image=alpine --labels=role=trusted --rm -it -- wget -qO- --timeout=3 http://web
```

## Check Your Understanding

**Q1: What's the default Pod-to-Pod networking behavior in Kubernetes without any NetworkPolicy?**

<details><summary>Answer</summary>

Fully open - any Pod can reach any other Pod, with no restrictions at all.

</details>

**Q2: What does a NetworkPolicy with podSelector matching web Pods and an empty ingress: list do?**

<details><summary>Answer</summary>

Denies ALL incoming traffic to those Pods - an empty ingress rule list under policyTypes: [Ingress] means nothing is allowed in.

</details>

**Q3: Does applying BOTH deny-all-to-web and allow-trusted-to-web policies together make sense, or do they conflict?**

<details><summary>Answer</summary>

They combine, not conflict - having any NetworkPolicy selecting a Pod switches it to default-deny for that traffic direction, and each policy's rules are additive (union) with any others also selecting it.

</details>

## Common Mistakes

- **Assuming NetworkPolicy support is automatic in every cluster** - It requires a CNI plugin that actually enforces NetworkPolicy (kind's default does, via kindnet in recent versions, but not all CNIs do) - always verify enforcement is actually happening, as you did above, rather than assuming.
- **Writing a NetworkPolicy and expecting it to affect Pods it doesn't select** - A NetworkPolicy only affects Pods matching its own podSelector - it has zero effect on any other Pods in the cluster.

## Cleanup

```bash
kubectl delete -f deny-all.yaml -f allow-trusted.yaml
kubectl delete deployment,service web
rm -f deny-all.yaml allow-trusted.yaml
```
