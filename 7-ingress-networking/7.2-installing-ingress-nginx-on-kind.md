# 7.2 Installing ingress-nginx on kind

## Concept Recap

kind needs a specially-configured cluster (with extra port mappings) for Ingress to actually be reachable from your host machine - a common beginner stumbling block.

## Objective

Correctly set up a kind cluster for Ingress and install the ingress-nginx controller.

## Prerequisites

- Lab 7.1 complete
- Lab 5.5 complete (cluster config syntax)

## Steps

### Step 1: Recreate your cluster WITH the required port mappings

```bash
kind delete cluster --name learning 2>/dev/null || true
cat > kind-ingress.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    kubeadmConfigPatches:
      - |
        kind: InitConfiguration
        nodeRegistration:
          kubeletExtraArgs:
            node-labels: "ingress-ready=true"
    extraPortMappings:
      - containerPort: 80
        hostPort: 80
        protocol: TCP
      - containerPort: 443
        hostPort: 443
        protocol: TCP
EOF
kind create cluster --name learning --config kind-ingress.yaml
```

Without extraPortMappings, ingress-nginx will install but you'll never be able to reach it from your host - this is THE most common Ingress-on-kind mistake.

### Step 2: Install ingress-nginx

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml
```

### Step 3: Wait for it to be ready

```bash
kubectl wait --namespace ingress-nginx --for=condition=ready pod --selector=app.kubernetes.io/component=controller --timeout=120s
```

### Step 4: Confirm it's actually listening on your host

```bash
curl -I http://localhost
```

You should get an HTTP response (likely a 404 from nginx, which is fine - it means the controller is reachable; a 404 here just means no Ingress rule matches yet).


## Try It Yourself

**Exercise 1:** Deliberately remove the extraPortMappings section, recreate the cluster, reinstall ingress-nginx, and confirm curl now fails - to see the failure mode you're avoiding.

<details><summary>Hint (try first without peeking)</summary>

Without the port mapping, `curl http://localhost` will simply fail to connect, since nothing on your actual host is listening.

</details>

## Check Your Understanding

**Q1: Why does a plain `kind create cluster` (no config file) not support reachable Ingress?**

<details><summary>Answer</summary>

Without extraPortMappings, nothing forwards traffic from your host's ports 80/443 into the kind cluster's Docker container - the controller runs, but is unreachable from outside.

</details>

**Q2: What confirms the ingress-nginx controller is actually ready?**

<details><summary>Answer</summary>

`kubectl wait ... --for=condition=ready` succeeding, or manually checking `kubectl get pods -n ingress-nginx` for Running status.

</details>

## Common Mistakes

- **Using a plain `kind create cluster` and being confused why Ingress 'doesn't work'** - This is almost always the extraPortMappings issue - always use the config file shown above for any kind cluster you plan to use with Ingress.
- **Not waiting for the controller pod to be ready before testing** - Applying the Ingress controller manifests doesn't mean it's immediately ready - always wait or check pod status first.
