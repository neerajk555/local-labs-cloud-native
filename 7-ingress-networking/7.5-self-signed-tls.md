# 7.5 Self-Signed TLS Termination

## Concept Recap

Ingress can terminate TLS (HTTPS) for you, so your backend Services can stay on plain HTTP internally while external traffic is encrypted.

## Objective

Generate a self-signed certificate and configure an Ingress to use it.

## Prerequisites

- Lab 7.3 complete
- openssl installed
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Generate a self-signed cert for a.local

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout tls.key -out tls.crt -subj '/CN=a.local'
```

### Step 2: Create a TLS Secret from it

```bash
kubectl create secret tls a-local-tls --cert=tls.crt --key=tls.key
```

### Step 3: Deploy a backend and reference the Secret in the Ingress

```bash
kubectl create deployment app-a --image=hashicorp/http-echo -- -text='secure response'
kubectl expose deployment app-a --port=5678
cat > ingress-tls.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: tls-demo
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - a.local
      secretName: a-local-tls
  rules:
    - host: a.local
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: app-a
                port:
                  number: 5678
EOF
kubectl apply -f ingress-tls.yaml
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `ingress-tls.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `ingress-tls.yaml`).
2. Paste this content and save (`Ctrl+S`):

### Step 4: Test over HTTPS (with -k, since it's self-signed)

```bash
curl -k -H 'Host: a.local' https://localhost/
```

-k tells curl to ignore the certificate warning - expected and fine for a self-signed cert in a lab.

## Check Your Understanding

**Q1: What does the -k flag do in curl?**

<details><summary>Answer</summary>

Tells curl to skip TLS certificate verification - necessary here only because the cert is self-signed and not issued by a trusted CA.

</details>

**Q2: Where does TLS termination happen in this setup?**

<details><summary>Answer</summary>

At the Ingress controller - external traffic is encrypted (HTTPS) up to the controller, but the backend Service/Pod typically still receives plain HTTP internally.

</details>

**Q3: Would you use a self-signed certificate in real production?**

<details><summary>Answer</summary>

No - use a certificate from a trusted CA (often automated via cert-manager and Let's Encrypt) for anything public-facing; self-signed certs are fine for local learning/testing only.

</details>

## Common Mistakes

- **Forgetting to list the hostname under tls.hosts in the Ingress** - Without it, the Ingress controller won't know which certificate to present for that hostname.
- **Being alarmed by the certificate warning instead of understanding why it's expected** - It's expected for any self-signed cert - the warning is the browser/curl correctly doing its job, not a sign something is broken.

## Cleanup

```bash
kubectl delete -f ingress-tls.yaml
kubectl delete secret a-local-tls
kubectl delete deployment,service app-a
rm -f tls.key tls.crt ingress-tls.yaml
```
