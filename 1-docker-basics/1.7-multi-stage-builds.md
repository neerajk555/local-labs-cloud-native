# 1.7 Multi-Stage Builds

## Concept Recap

A multi-stage build uses one stage to compile/build your app (with all the heavy build tools) and a second, much smaller stage to actually run it - keeping the final image lean.

## Objective

Shrink an image by separating build-time tools from the runtime image.

## Prerequisites

- Lab 1.6 complete

## Steps

### Step 1: Build a single-stage version and note its size

```bash
cd myapp 2>/dev/null || (mkdir myapp && cd myapp && echo "require('http').createServer((req,res)=>res.end('hi')).listen(3000)" > index.js)
cat > Dockerfile <<'EOF'
FROM node:20
WORKDIR /app
COPY index.js .
CMD ["node", "index.js"]
EOF
docker build -t myapp:single .
docker images myapp:single
```

### Step 2: Rewrite as a multi-stage build

```bash
cat > Dockerfile <<'EOF'
FROM node:20 AS build
WORKDIR /app
COPY index.js .

FROM node:20-slim
WORKDIR /app
COPY --from=build /app/index.js .
CMD ["node", "index.js"]
EOF
docker build -t myapp:multi .
docker images myapp:multi
```

### Step 3: Compare sizes

```bash
docker images | grep myapp
```


## Try It Yourself

**Exercise 1:** Identify which lines in the multi-stage Dockerfile belong to the 'build' stage and which belong to the final runtime stage.

<details><summary>Hint (try first without peeking)</summary>

Everything before the second `FROM` is the build stage, named `build`; everything after is the runtime stage that only copies the final artifact.

</details>

## Check Your Understanding

**Q1: What does `COPY --from=build` do?**

<details><summary>Answer</summary>

It copies a file from a NAMED EARLIER STAGE (here, 'build') into the current stage, instead of from your host machine.

</details>

**Q2: Why is the final image smaller in a multi-stage build?**

<details><summary>Answer</summary>

The final stage only includes the runtime base image plus the specific artifacts copied over - none of the build tools/intermediate files from the build stage are included.

</details>

**Q3: Do you need to name build stages with AS?**

<details><summary>Answer</summary>

No, it's optional, but naming them (like `AS build`) makes `COPY --from=` far more readable than referencing them by number.

</details>

## Common Mistakes

- **Forgetting --from= and just using COPY** - That copies from your host machine, not from an earlier build stage - you'll get a 'file not found' error or copy the wrong thing.
- **Using the full node:20 image in the runtime stage too** - This defeats the purpose - use a slim/alpine variant for the final stage to actually save space.

## Cleanup

```bash
docker rmi myapp:single myapp:multi
cd .. && rm -rf myapp
```
