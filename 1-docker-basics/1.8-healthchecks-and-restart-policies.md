# 1.8 Health Checks and Restart Policies

## Concept Recap

Docker can periodically check if your app is actually working (not just running) via a health check, and can automatically restart a container that crashes via a restart policy.

## Objective

Configure and observe both a health check and a restart policy.

## Prerequisites

- Module 0 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Run with a health check

```bash
docker run -d --name health-demo --health-cmd='curl -f http://localhost/ || exit 1' --health-interval=10s --health-retries=3 nginx
```

### Step 2: Watch the health status change over time

```bash
watch docker inspect --format='{{.State.Health.Status}}' health-demo
```

Press Ctrl+C to stop watching once you see 'healthy'.

### Step 3: Run with a restart policy

```bash
docker run -d --name restart-demo --restart=unless-stopped alpine sh -c 'sleep 5 && exit 1'
```

### Step 4: Watch it restart automatically after crashing

```bash
watch docker ps -a --filter name=restart-demo
```

You'll see the RESTARTS count increase every ~5 seconds.


## Try It Yourself

**Exercise 1:** Try `--restart=on-failure:3` instead of `unless-stopped` on a new container that always exits with an error. What's different about how many times it restarts?

<details><summary>Hint (try first without peeking)</summary>

`on-failure:3` caps automatic restarts at 3 attempts, then gives up; `unless-stopped` keeps trying indefinitely.

</details>

## Check Your Understanding

**Q1: What's the difference between a container being 'running' and being 'healthy'?**

<details><summary>Answer</summary>

Running just means the main process hasn't exited; healthy means the health check command is actually succeeding, confirming the app works, not just that the process exists.

</details>

**Q2: What does --restart=unless-stopped do differently from --restart=always?**

<details><summary>Answer</summary>

unless-stopped won't restart the container if YOU explicitly stopped it (e.g. via `docker stop`) - always will restart it even after a manual stop, including after a host reboot.

</details>

**Q3: Why might a container be 'running' but 'unhealthy'?**

<details><summary>Answer</summary>

The process is alive, but the health check command (e.g. hitting a specific endpoint) is failing - useful for catching apps that are frozen or serving errors despite still running.

</details>

## Common Mistakes

- **Assuming a running container is automatically working correctly** - Running only means the process hasn't exited - always add a health check for anything user-facing.
- **Using --restart=always for a container you expect to sometimes stop deliberately** - This will fight you - it restarts even after `docker stop`. Use unless-stopped instead for most cases.
