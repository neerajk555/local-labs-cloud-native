# 1.11 Mini-Project: Containerize a Web App End-to-End

## Concept Recap

This project combines everything from Module 1: writing a Dockerfile, multi-stage builds, port mapping, volumes, environment variables, health checks, and networking basics.

## Objective

Take a provided small app and containerize it completely on your own, using a checklist instead of step-by-step instructions.

## Prerequisites

- Labs 1.1-1.10 complete

## Steps

### Step 1: Starter app

Create this simple app yourself:

```bash
mkdir project1 && cd project1
cat > index.js <<'EOF'
const http = require('http');
const PORT = process.env.PORT || 3000;
const MESSAGE = process.env.MESSAGE || 'default message';
http.createServer((req, res) => res.end(MESSAGE)).listen(PORT);
EOF
```

### Step 2: Your checklist (no step-by-step this time)

Using only what you've learned in Labs 1.1-1.10, without looking back unless you're stuck:

1. Write a **multi-stage** Dockerfile for this app
2. Build it, tagged `project1:v1`
3. Run it with the `MESSAGE` environment variable set to something custom
4. Map it to host port 4000
5. Add a health check that curls the app
6. Add a restart policy of `unless-stopped`
7. Put it on a user-defined network named `project1-net`
8. Verify everything: the message is correct, the health check passes, and the container survives a manual crash (kill the node process inside with `docker exec` and watch it restart)


## Try It Yourself

**Exercise 1:** Once everything works, deliberately break your own health check (e.g. curl the wrong path) and confirm the health status correctly reports 'unhealthy'.

<details><summary>Hint (try first without peeking)</summary>

Change --health-cmd to curl a path that returns 404, then check `docker inspect --format='{{.State.Health.Status}}'`.

</details>

## Check Your Understanding

**Q1: Self-check: can you explain, without notes, why you put COPY package.json before COPY . . if your app had dependencies?**

<details><summary>Answer</summary>

For layer caching - see Lab 1.6/1.7 if you're unsure.

</details>

**Q2: Self-check: what would happen to MESSAGE if you didn't set -e MESSAGE=... at all?**

<details><summary>Answer</summary>

It would fall back to the default value hardcoded in the app ('default message'), since the environment variable would be undefined.

</details>

## Common Mistakes

- **Skipping the checklist items you find 'boring' (health checks, restart policy)** - These are exactly the things beginners skip and then struggle with later - do all 8 steps.
- **Not testing the crash-recovery step** - This is the only way to actually verify your restart policy works, rather than just assuming the flag did something.

## Cleanup

```bash
docker rm -f $(docker ps -aq --filter name=project1) 2>/dev/null || true
docker network rm project1-net 2>/dev/null || true
cd .. && rm -rf project1
```
