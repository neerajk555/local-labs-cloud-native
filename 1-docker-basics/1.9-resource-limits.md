# 1.9 Resource Limits

## Concept Recap

By default, a container can use as much CPU/memory as the host allows, which can let one misbehaving container starve everything else. Limits cap this.

## Objective

Set and verify CPU and memory limits on a container.

## Prerequisites

- Module 0 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Run with limits

```bash
docker run -d --name limited --memory=128m --cpus=0.5 nginx
```

### Step 2: Verify the limits took effect

```bash
docker inspect limited --format='Memory: {{.HostConfig.Memory}} bytes, NanoCPUs: {{.HostConfig.NanoCpus}}'
```

### Step 3: Watch live resource usage

```bash
docker stats limited --no-stream
```

## Check Your Understanding

**Q1: What happens if a container tries to use more memory than its --memory limit?**

<details><summary>Answer</summary>

The kernel's OOM (out-of-memory) killer terminates it - check `docker inspect --format='{{.State.OOMKilled}}'` to confirm this happened.

</details>

**Q2: Does --cpus=0.5 mean the container can only use one specific CPU core?**

<details><summary>Answer</summary>

No - it means the container can use up to 50% of ONE CPU's worth of processing time, potentially spread across cores, not a specific physical core.

</details>

**Q3: Why set resource limits at all in a shared environment?**

<details><summary>Answer</summary>

To prevent one container from starving others (or the host itself) of CPU or memory, which is critical on shared machines like a training account or production cluster.

</details>

## Common Mistakes

- **Not setting any limits in a shared or training environment** - One runaway container can degrade everything else running on the same host.
- **Setting memory limits too low for the app's actual needs** - This causes unexpected OOM kills - check the app's real usage with `docker stats` first before capping it.

## Cleanup

```bash
docker rm -f limited oom-test 2>/dev/null || true
```
