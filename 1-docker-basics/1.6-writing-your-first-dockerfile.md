# 1.6 Writing Your First Dockerfile From Scratch

## Concept Recap

Having read one in Lab 0.4, you'll now write your own Dockerfile for a tiny app and build it into an image.

## Objective

Write, build, and run a Dockerfile for a minimal Node.js app.

## Prerequisites

- Lab 0.4 complete

## Steps

### Step 1: Create a tiny app

```bash
mkdir myapp && cd myapp
cat > index.js <<'EOF'
require('http').createServer((req, res) => res.end('Hello from my container!')).listen(3000);
EOF
```

### Step 2: Write the Dockerfile

```bash
cat > Dockerfile <<'EOF'
FROM node:20-slim
WORKDIR /app
COPY index.js .
EXPOSE 3000
CMD ["node", "index.js"]
EOF
```

### Step 3: Build the image

```bash
docker build -t myapp:v1 .
```

### Step 4: Run a container from it

```bash
docker run -d --name myapp-container -p 3000:3000 myapp:v1
```

Visit http://localhost:3000

## Check Your Understanding

**Q1: What does the `-t myapp:v1` flag do during `docker build`?**

<details><summary>Answer</summary>

It tags (names) the resulting image so you can reference it later instead of using its long hash ID.

</details>

**Q2: What does the `.` at the end of `docker build -t myapp:v1 .` mean?**

<details><summary>Answer</summary>

It's the build context - the directory Docker sends to the build process, and where it looks for the Dockerfile by default.

</details>

**Q3: If you change index.js and rebuild without changing the tag, what happens to the old myapp:v1 image?**

<details><summary>Answer</summary>

It becomes untagged (a 'dangling' image, shown as <none> in `docker images`) unless you gave it a different tag first.

</details>

## Common Mistakes

- **Forgetting to rebuild after changing source code** - Docker doesn't auto-detect source changes - you must explicitly run `docker build` again.
- **Building from the wrong directory** - The build context is wherever you run `docker build ... <path>` from - make sure your Dockerfile and source files are actually there.

## Cleanup

```bash
docker rm -f myapp-container myapp-v2 2>/dev/null || true
cd .. && rm -rf myapp
```
