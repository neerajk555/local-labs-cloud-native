# 1.1 Container Lifecycle: Run, Stop, Remove

## Concept Recap

Containers move through a lifecycle: created → running → stopped → removed. Understanding this explicitly avoids a lot of beginner confusion about why a container 'disappeared' or won't restart.

## Objective

Practice every stage of a container's lifecycle deliberately.

## Prerequisites

- Module 0 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Run a long-lived container in the background

```bash
docker run -d --name lifecycle-demo nginx
```

### Step 2: Check it's running

```bash
docker ps
```

### Step 3: Stop it (graceful shutdown)

```bash
docker stop lifecycle-demo
```

### Step 4: See it still exists, just stopped

```bash
docker ps -a
```

### Step 5: Start it again (same container, same filesystem state)

```bash
docker start lifecycle-demo
```

### Step 6: Remove it (must be stopped first, or use -f)

```bash
docker stop lifecycle-demo
docker rm lifecycle-demo
```


## Try It Yourself

**Exercise 1:** Run a new container named `quick-test` from nginx, then remove it in one step using `docker rm -f`. What does `-f` do?

<details><summary>Hint (try first without peeking)</summary>

`-f` force-stops a running container before removing it, skipping the separate `docker stop` step.

</details>

## Check Your Understanding

**Q1: What's the difference between `docker stop` and `docker rm`?**

<details><summary>Answer</summary>

`stop` halts a running container but keeps it (and its filesystem state) around; `rm` permanently deletes it.

</details>

**Q2: If you `docker start` a previously stopped container, does it keep its earlier filesystem changes?**

<details><summary>Answer</summary>

Yes - stopping doesn't erase anything, only removing does.

</details>

**Q3: Can you `docker rm` a running container without `-f`?**

<details><summary>Answer</summary>

No - you'll get an error; either stop it first or use `docker rm -f`.

</details>

## Common Mistakes

- **Trying to `docker rm` a running container** - You'll get 'container is running' - stop it first or use `-f`.
- **Assuming `docker stop` deletes data** - It doesn't - the container and its writable layer persist until `docker rm`.

## Cleanup

```bash
docker rm -f lifecycle-demo quick-test 2>/dev/null || true
```
