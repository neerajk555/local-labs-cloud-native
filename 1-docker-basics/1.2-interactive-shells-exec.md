# 1.2 Interactive Shells Inside a Container

## Concept Recap

`docker exec` runs a new command inside an ALREADY-RUNNING container - it doesn't start a new container. This is your main tool for inspecting/debugging a running container from the inside.

## Objective

Get a shell inside a running container and explore its filesystem and processes.

## Prerequisites

- Lab 1.1 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Start a container to explore

```bash
docker run -d --name explore nginx
```

### Step 2: Get an interactive shell inside it

```bash
docker exec -it explore bash
```

### Step 3: Look around (inside the container's shell)

```bash
ls /usr/share/nginx/html
ps aux
exit
```

Type `exit` to leave the shell - this does NOT stop the container, just your shell session inside it.

### Step 4: Run a one-off command without a full shell

```bash
docker exec explore cat /etc/os-release
```

## Check Your Understanding

**Q1: Does exiting a `docker exec` shell stop the container?**

<details><summary>Answer</summary>

No - it only ends your shell session. The container keeps running whatever its main process is.

</details>

**Q2: What's the difference between `docker run` and `docker exec`?**

<details><summary>Answer</summary>

`run` creates and starts a NEW container; `exec` runs a command inside an EXISTING running container.

</details>

**Q3: Why might `docker exec -it mycontainer sh` work when `bash` doesn't?**

<details><summary>Answer</summary>

Some minimal images (like alpine) don't include bash - `sh` is more universally available.

</details>

## Common Mistakes

- **Trying to exec into a stopped container** - You'll get an error - the container's main process must be running for exec to attach to its namespace.
- **Confusing exec with attach** - `docker attach` connects to the container's MAIN process's own stdin/stdout, which can be risky (Ctrl+C might kill it); `exec` starts a separate process, which is safer for exploration.
