# 5.6 Choosing the Right Workload Type (Decision-Tree Exercise)

## Concept Recap

This lab is a pure exercise in applying everything from this module - no new commands, just decision-making practice.

## Objective

Correctly classify 8 real-world scenarios into Deployment, Job, CronJob, StatefulSet, or DaemonSet.

## Prerequisites

- Labs 5.1-5.5 complete

## Steps

### Step 1: The decision tree

Ask in order:
1. Does this need to run on EVERY node? → DaemonSet
2. Does this need to run once/occasionally to completion, not continuously? → Job (one-off) or CronJob (scheduled)
3. Do individual replicas need stable identity and/or ordered startup? → StatefulSet
4. Otherwise (stateless, continuous, interchangeable replicas) → Deployment

### Step 2: Classify these 8 scenarios yourself before checking the quiz

A) A stateless REST API with 5 replicas
B) A nightly database backup script
C) A 3-node Kafka cluster where each broker has a distinct ID and stable storage
D) A security scanning agent that must inspect every node's filesystem
E) A one-time database schema migration when deploying a new app version
F) A React frontend served by nginx, 3 replicas
G) A weekly report-generation task
H) A log-shipping agent forwarding each node's logs to a central store

## Common Mistakes

- **Defaulting to Deployment for everything** - It's the most common choice, but not universal - always check the decision tree above, especially for anything stateful, scheduled, or node-level.
- **Confusing Job and CronJob** - Job = runs once, right now, to completion. CronJob = creates Jobs repeatedly on a schedule. A CronJob is really 'Job + a schedule,' not a separate execution model.
