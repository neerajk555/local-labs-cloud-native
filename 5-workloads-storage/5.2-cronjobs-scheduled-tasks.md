# 5.2 CronJobs: Scheduled Tasks

## Concept Recap

A CronJob creates a new Job on a schedule, using standard cron syntax - useful for recurring tasks like backups or report generation.

## Objective

Create a CronJob and watch it spawn Jobs on schedule.

## Prerequisites

- Lab 5.1 complete

## Steps

### Step 1: Create a CronJob running every minute

```bash
kubectl create cronjob minute-task --image=busybox --schedule='* * * * *' -- echo 'tick'
```

### Step 2: Wait a couple minutes, then see the Jobs it created

```bash
kubectl get jobs
```

You should see a new Job appear roughly every 60 seconds, named like minute-task-<timestamp>.

### Step 3: See the actual output from one

```bash
kubectl get pods
kubectl logs <paste-a-pod-name-from-a-minute-task-job>
```

## Check Your Understanding

**Q1: What creates the actual Job objects for a CronJob?**

<details><summary>Answer</summary>

The CronJob controller, automatically, based on the schedule you defined - each scheduled run gets its own Job object.

</details>

**Q2: What cron syntax runs a task every minute?**

<details><summary>Answer</summary>

`* * * * *`.

</details>

**Q3: Why might you want concurrencyPolicy: Forbid on a CronJob?**

<details><summary>Answer</summary>

To prevent overlapping runs of a task that shouldn't run concurrently with itself, like a backup that writes to the same location each time.

</details>

## Common Mistakes

- **Forgetting old Jobs/Pods from a CronJob accumulate over time** - By default a history of recent successful/failed Jobs is kept (`successfulJobsHistoryLimit`/`failedJobsHistoryLimit`) - tune these for long-running CronJobs to avoid clutter.

## Cleanup

```bash
kubectl delete cronjob minute-task
```
