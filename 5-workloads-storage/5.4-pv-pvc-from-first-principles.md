# 5.4 Persistent Volumes and Claims, From First Principles

## Concept Recap

A **PersistentVolume (PV)** is a piece of storage in the cluster (like a disk). A **PersistentVolumeClaim (PVC)** is a REQUEST for storage by a Pod - matching the Docker concept of a named volume (Lab 1.4), but at cluster scale with a request/fulfillment model.

## Objective

Create a PVC, use it in a Pod, and prove data survives Pod deletion.

## Prerequisites

- Lab 1.4 complete
- Lab 4.2 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Create a PVC (kind auto-provisions the underlying storage)

```bash
cat > pvc.yaml <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
EOF
kubectl apply -f pvc.yaml
kubectl get pvc
```

### Step 2: Mount it in a Pod and write data

```bash
cat > pod-with-pvc.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: pvc-demo
spec:
  containers:
    - name: app
      image: busybox
      command: ["sleep", "3600"]
      volumeMounts:
        - name: data
          mountPath: /data
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: my-pvc
EOF
kubectl apply -f pod-with-pvc.yaml
kubectl exec pvc-demo -- sh -c 'echo persisted-data > /data/file.txt'
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 3: Delete and recreate the Pod, same PVC

```bash
kubectl delete pod pvc-demo
kubectl apply -f pod-with-pvc.yaml
kubectl exec pvc-demo -- cat /data/file.txt
```

The file survived Pod deletion, because the data lived in the PVC, not the Pod's own filesystem.

## Check Your Understanding

**Q1: What's the difference between a PV and a PVC?**

<details><summary>Answer</summary>

A PV is the actual storage resource in the cluster; a PVC is a request for storage that gets matched (bound) to a suitable PV.

</details>

**Q2: If you delete a Pod using a PVC, does the data disappear?**

<details><summary>Answer</summary>

No - the data lives in the PVC/PV, independent of any specific Pod's lifecycle, exactly like a Docker named volume outliving a container.

</details>

**Q3: What does accessModes: ReadWriteOnce mean?**

<details><summary>Answer</summary>

The volume can be mounted as read-write by a single node at a time - other access modes exist for shared/multi-node scenarios.

</details>

## Common Mistakes

- **Assuming deleting the Pod deletes the data** - That's the whole point of PVCs - data outlives the Pod. You'd need to explicitly delete the PVC itself to lose the data.
- **Forgetting to delete the PVC and accumulating orphaned storage** - Run `kubectl get pvc` periodically in real clusters to spot unused claims still consuming storage.
