# 5.5 DaemonSets

## Concept Recap

A DaemonSet ensures exactly ONE copy of a Pod runs on EVERY node (or a chosen subset) - common for node-level agents like log collectors or monitoring exporters.

## Objective

Deploy a DaemonSet and confirm one Pod per node, including on a multi-node cluster.

## Prerequisites

- Lab 4.1 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Recreate your kind cluster with multiple nodes

```bash
kind delete cluster --name learning 2>/dev/null || true
cat > kind-multi-node.yaml <<'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
EOF
kind create cluster --name learning --config kind-multi-node.yaml
kubectl get nodes
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `kind-multi-node.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `kind-multi-node.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 2: Deploy a DaemonSet

```bash
cat > daemonset.yaml <<'EOF'
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-agent
spec:
  selector:
    matchLabels:
      app: node-agent
  template:
    metadata:
      labels:
        app: node-agent
    spec:
      containers:
        - name: agent
          image: busybox
          command: ["sleep", "3600"]
EOF
kubectl apply -f daemonset.yaml
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `daemonset.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `daemonset.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-agent
spec:
  selector:
    matchLabels:
      app: node-agent
  template:
    metadata:
      labels:
        app: node-agent
    spec:
      containers:
        - name: agent
          image: busybox
          command: ["sleep", "3600"]
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 3: Confirm one Pod per node

```bash
kubectl get pods -o wide -l app=node-agent
```

You should see exactly 3 Pods (one per node, including the control-plane node unless it's tainted against scheduling), each on a DIFFERENT node.

## Check Your Understanding

**Q1: How many replicas do you specify for a DaemonSet?**

<details><summary>Answer</summary>

None - you don't set a replica count at all; it automatically runs exactly one Pod per matching node, growing/shrinking as nodes are added/removed.

</details>

**Q2: Give a real-world example of when you'd use a DaemonSet.**

<details><summary>Answer</summary>

A log-collection agent (like Fluentd) or monitoring exporter (like node-exporter) that needs to run on every node to gather node-level data.

</details>

## Common Mistakes

- **Trying to set `replicas:` on a DaemonSet** - DaemonSets don't have a replicas field - the node count IS the replica count, automatically.
- **Testing DaemonSets on a single-node cluster and being confused there's only 1 Pod** - That's correct behavior for 1 node - you need a multi-node cluster (as set up above) to see the real per-node behavior.
