# 0.2 Your First Container

## Concept Recap

`docker run` does three things in one command: it downloads ("pulls") an image if you don't have it locally, creates a new container from that image, and starts it. An **image** is a read-only template (like a class); a **container** is a running instance of that template (like an object).

## Objective

Run your very first container and understand exactly what each part of the command does.

## Prerequisites

- Docker installed and running (`docker version` should show both a Client and Server section)

## Steps

### Step 1: Run hello-world

```bash
docker run hello-world
```

Read the output carefully - it explains, in Docker's own words, the exact steps it just took: contacting Docker Hub, downloading the image, creating a container, and running it.

### Step 2: See the container that ran (and exited)

```bash
docker ps -a
```

`-a` shows ALL containers, including ones that finished running. Without `-a`, `docker ps` only shows currently running containers - and hello-world exits immediately after printing its message.

### Step 3: See the image that was downloaded

```bash
docker images
```

This is the template. You can create as many containers from this one image as you like.


## Try It Yourself

**Exercise 1:** Run `docker run hello-world` a second time. Does it download the image again? Check the output for the difference.

<details><summary>Hint (try first without peeking)</summary>

Look for the phrase about pulling - the second run should be noticeably faster since the image is now cached locally.

</details>

**Exercise 2:** Run `docker run -it ubuntu bash`, then type `ls` and `exit`. What did you just do?

<details><summary>Hint (try first without peeking)</summary>

You started a full Ubuntu container and got an interactive shell inside it - `-it` means interactive + attach a terminal.

</details>

## Check Your Understanding

**Q1: What's the difference between an image and a container?**

<details><summary>Answer</summary>

An image is a read-only template; a container is a running (or stopped) instance created from that template.

</details>

**Q2: Why does `docker ps` show nothing after running hello-world, but `docker ps -a` shows it?**

<details><summary>Answer</summary>

hello-world prints a message and exits immediately - `docker ps` only shows running containers, `-a` shows all, including stopped ones.

</details>

**Q3: What does the `-it` flag do?**

<details><summary>Answer</summary>

`-i` keeps STDIN open (interactive), `-t` allocates a pseudo-terminal - together they let you type into and see output from a shell inside the container.

</details>

## Common Mistakes

- **Expecting `docker ps` to show a finished container** - Use `docker ps -a` for stopped containers too.
- **Confusing 'pulling an image' with 'running a container'** - Pulling just downloads the template; `docker run` pulls (if needed) AND creates + starts a container from it.

## Cleanup

```bash
docker rm $(docker ps -aq --filter ancestor=hello-world)
```
