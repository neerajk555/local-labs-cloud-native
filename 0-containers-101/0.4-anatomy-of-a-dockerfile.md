# 0.4 Anatomy of a Dockerfile (Read-Only Walkthrough)

## Concept Recap

A Dockerfile is a recipe for building an image. Each instruction adds a layer. You won't write one yet - this lab is purely about reading and understanding one before Lab 1.6 has you write your own.

## Objective

Read an existing Dockerfile line by line and explain what each instruction does.

## Prerequisites

- Labs 0.1-0.3 complete

## Steps

### Step 1: Read this annotated example

```dockerfile
FROM node:20-slim        # Start from an existing base image (Node.js pre-installed)
WORKDIR /app              # All following commands run from /app inside the image
COPY package.json .       # Copy just this file first (see 'layer caching' note below)
RUN npm install           # Run a command during the BUILD (not when the container starts)
COPY . .                  # Copy the rest of the source code
EXPOSE 3000                # Documentation only - doesn't actually publish the port
CMD ["node", "index.js"] # The command that runs when a CONTAINER starts
```

### Step 2: Understand layer caching

Docker caches each instruction's result as a layer. If `package.json` hasn't changed, Docker reuses the cached `RUN npm install` layer instead of re-running it - this is why `COPY package.json .` happens before `COPY . .`: it lets dependency installation be cached separately from source code changes, which change far more often.


## Try It Yourself

**Exercise 1:** Without running anything, predict what would happen if you swapped the order - `COPY . .` before `COPY package.json .` and `RUN npm install`. Why is this slower to rebuild?

<details><summary>Hint (try first without peeking)</summary>

Any source code change would now invalidate the cache for the COPY step above npm install, forcing a full reinstall every time you edit any file.

## Check Your Understanding

**Q1: What's the difference between RUN and CMD?**

<details><summary>Answer</summary>

RUN executes during image build (baked into the image); CMD defines the default command that runs when a container starts from the image.

</details>

**Q2: Does EXPOSE actually publish a port to your host machine?**

<details><summary>Answer</summary>

No - it's documentation/metadata. You still need `-p` on `docker run` to actually map a port.

</details>

**Q3: Why copy package.json before the rest of the source code?**

<details><summary>Answer</summary>

So Docker can cache the dependency-install layer separately, avoiding a full reinstall on every source change.

</details>

## Common Mistakes

- **Thinking EXPOSE publishes a port** - It doesn't - it's purely informational. Use `-p hostPort:containerPort` on `docker run`.
- **Putting COPY . . before installing dependencies** - This busts the dependency-cache layer on every code change, making builds much slower.
