# 6.6 Packaging, Versioning, Upgrading, Rolling Back

## Concept Recap

Charts get packaged into versioned `.tgz` archives for distribution, and Helm tracks a full revision history per release, just like `kubectl rollout` (Lab 4.8) but for the whole chart.

## Objective

Package your chart, install it, upgrade it, and roll back a bad upgrade.

## Prerequisites

- Labs 6.3-6.5 complete

## Steps

### Step 1: Package the chart

```bash
cd mychart
helm package .
ls *.tgz
```

### Step 2: Install from the packaged archive

```bash
helm install final-test ./mychart-0.1.0.tgz
```

### Step 3: Bump the chart version and make a change

```bash
sed -i 's/version: 0.1.0/version: 0.2.0/' Chart.yaml
sed -i 's/replicaCount: 1/replicaCount: 3/' values.yaml
helm package .
helm upgrade final-test ./mychart-0.2.0.tgz
```

### Step 4: Confirm the upgrade applied

```bash
kubectl get pods -l app.kubernetes.io/instance=final-test
```

### Step 5: See revision history

```bash
helm history final-test
```

### Step 6: Roll back to the previous revision

```bash
helm rollback final-test 1
kubectl get pods -l app.kubernetes.io/instance=final-test
```

Replica count should be back to 1.

## Check Your Understanding

**Q1: What command creates a distributable, versioned archive of a chart?**

<details><summary>Answer</summary>

`helm package .`, which produces a `.tgz` file named after the chart and its version.

</details>

**Q2: What command shows a release's full upgrade history?**

<details><summary>Answer</summary>

`helm history <release-name>`.

</details>

**Q3: Does `helm rollback` require you to have the old chart files still on disk?**

<details><summary>Answer</summary>

No - Helm stores enough information about each release's state to roll back using only the release name and target revision number.

</details>

## Common Mistakes

- **Forgetting to bump the version in Chart.yaml before repackaging** - Helm won't stop you from reusing a version number, but it defeats the purpose of versioning - always bump on real changes.
- **Assuming rollback undoes changes to values.yaml on disk** - It doesn't touch your local files at all - it only changes what's DEPLOYED, by re-applying a previous release's recorded state.

## Cleanup

```bash
helm uninstall final-test
cd .. && rm -rf mychart
```
