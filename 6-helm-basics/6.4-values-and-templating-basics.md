# 6.4 Values and Templating Basics

## Concept Recap

Helm's templating uses Go template syntax: `{{ .Values.xxx }}` pulls a value from values.yaml (or a --set override) into the rendered YAML.

## Objective

Add your own custom value and reference it in a template.

## Prerequisites

- Lab 6.3 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Add a custom value

```bash
cd mychart
echo 'greeting: hello-from-helm' >> values.yaml
```

### Step 2: Reference it via an environment variable in the Deployment template

Open `templates/deployment.yaml` and add this under the container spec (indentation matters in YAML):

```yaml
          env:
            - name: GREETING
              value: {{ .Values.greeting | quote }}
```

### Step 3: Render the template WITHOUT installing, to check your work

```bash
helm template . | grep -A2 GREETING
```

This is the safest way to check templating changes before actually applying them to a cluster.

### Step 4: Install and verify inside the running Pod

```bash
helm install templating-test .
kubectl get pods -l app.kubernetes.io/instance=templating-test
kubectl exec <paste-pod-name> -- env | grep GREETING
```

## Check Your Understanding

**Q1: What does `helm template .` do, and why is it useful before `helm install`?**

<details><summary>Answer</summary>

It renders the chart's templates into plain YAML LOCALLY, without touching the cluster - letting you catch templating mistakes before actually deploying anything.

</details>

**Q2: What does the `| quote` pipe do in `{{ .Values.greeting | quote }}`?**

<details><summary>Answer</summary>

It wraps the value in quotes in the rendered YAML - important for values that might otherwise be interpreted as a different YAML type (like a number or boolean) instead of a string.

</details>

**Q3: Does --set permanently change values.yaml?**

<details><summary>Answer</summary>

No - it only overrides the value for that specific install/upgrade command; the file on disk is unchanged.

</details>

## Common Mistakes

- **Skipping helm template and going straight to helm install** - Any YAML indentation or templating syntax error is much easier to catch locally with `helm template` than after a failed cluster deployment.
- **Forgetting `| quote` and getting unexpected YAML type errors** - Go templates output raw text - without quoting, a value like `yes` or `123` might be interpreted as a boolean/number by YAML instead of a string.
