# 6.2 Installing a Public Chart (Before Authoring Your Own)

## Concept Recap

Before writing a chart, experience using one someone else already wrote - this is also the most common real-world use of Helm (installing existing software like databases or monitoring stacks).

## Objective

Install, inspect, customize, and uninstall a public Helm chart.

## Prerequisites

- Lab 6.1 complete
- Helm installed
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Add a public chart repository

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
```

### Step 2: See what values are available before installing

```bash
helm show values bitnami/nginx | head -40
```

This is how you discover what's customizable BEFORE installing - always check this first.

### Step 3: Install it

```bash
helm install my-nginx bitnami/nginx
```

### Step 4: See what Helm created

```bash
helm list
kubectl get all -l app.kubernetes.io/instance=my-nginx
```

### Step 5: Customize a value and upgrade

```bash
helm upgrade my-nginx bitnami/nginx --set replicaCount=3
kubectl get pods -l app.kubernetes.io/instance=my-nginx
```

### Step 6: Uninstall cleanly

```bash
helm uninstall my-nginx
```

## Check Your Understanding

**Q1: What command shows you a chart's customizable values before installing it?**

<details><summary>Answer</summary>

`helm show values <repo>/<chart>`.

</details>

**Q2: What's a Helm 'release'?**

<details><summary>Answer</summary>

A specific installed instance of a chart, identified by the name you gave it (e.g. my-nginx) - you can have multiple independent releases of the same chart.

</details>

**Q3: What command cleanly removes everything a release created?**

<details><summary>Answer</summary>

`helm uninstall <release-name>`.

</details>

## Common Mistakes

- **Installing a chart without checking its values first** - You might miss important settings (like persistence, resource limits) that have consequences you didn't intend - always `helm show values` first.
- **Using kubectl delete to try to remove a Helm-installed app** - This can leave orphaned resources Helm doesn't know about - always use `helm uninstall` for anything installed via Helm.

## Cleanup

```bash
helm uninstall my-nginx my-nginx-2 2>/dev/null || true
```
