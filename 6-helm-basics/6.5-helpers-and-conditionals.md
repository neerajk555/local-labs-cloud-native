# 6.5 Helpers and Conditionals

## Concept Recap

Named templates (helpers) let you define a snippet once and reuse it everywhere (e.g. a consistent naming convention). Conditionals let a chart optionally include resources based on values.

## Objective

Add a named helper and a conditional block to your chart.

## Prerequisites

- Lab 6.4 complete

## Steps

### Step 1: Look at the existing helper Helm already generated

```bash
cd mychart
cat templates/_helpers.tpl | head -20
```

`helm create` already generates a `{{ include "mychart.fullname" . }}` helper used throughout the other templates - find where it's used in deployment.yaml.

### Step 2: Add a conditional resource

Add a new file `templates/optional-configmap.yaml`:

```yaml
{{- if .Values.enableExtraConfig }}
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "mychart.fullname" . }}-extra
data:
  note: "this only exists when enableExtraConfig is true"
{{- end }}
```

### Step 3: Add the corresponding value (defaulted to false)

```bash
echo 'enableExtraConfig: false' >> values.yaml
```

### Step 4: Render with the default (should be absent)

```bash
helm template . | grep -c 'extra' || echo 'not present, as expected'
```

### Step 5: Render with it enabled

```bash
helm template . --set enableExtraConfig=true | grep -A3 'extra'
```

## Check Your Understanding

**Q1: What does `{{- if .Values.enableExtraConfig }}` do?**

<details><summary>Answer</summary>

It only includes everything between this line and the matching `{{- end }}` in the rendered output IF that value is truthy - otherwise that whole block is omitted.

</details>

**Q2: What does `include "mychart.fullname" .` do?**

<details><summary>Answer</summary>

It calls a NAMED TEMPLATE (helper) defined elsewhere (in _helpers.tpl) and inserts its output - used here for a consistent resource-naming convention across all templates in the chart.

</details>

**Q3: Why use a shared helper for naming instead of hardcoding names in each template?**

<details><summary>Answer</summary>

Consistency and maintainability - if the naming convention needs to change, you change it in ONE place (the helper) instead of every template file.

</details>

## Common Mistakes

- **Forgetting the leading `-` in `{{- if ... }}`** - The `-` trims whitespace/newlines around the tag - without it, conditional blocks can leave stray blank lines in the rendered YAML, which is usually harmless but untidy and can occasionally cause parsing issues.
- **Not testing both the true AND false paths of a conditional** - Always verify both states render correctly, as done above with and without --set.
