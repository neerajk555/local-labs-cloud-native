# 2.4 Networking Between Services (DNS by Service Name)

## Concept Recap

Compose automatically creates a user-defined network for your whole app (Lab 1.10's concept) - every service can reach every other service by its SERVICE NAME, no manual network setup needed.

## Objective

Have one service call another by name, with zero manual networking.

## Prerequisites

- Lab 1.10 complete
- Lab 2.2 complete

## Steps

### Step 1: Define two services

```bash
mkdir net-demo && cd net-demo
cat > compose.yaml <<'EOF'
services:
  web:
    image: nginx
  tester:
    image: alpine
    command: sh -c "apk add --no-cache curl >/dev/null && sleep 3 && curl -s http://web:80 | head -5"
EOF
```

### Step 2: Bring it up and watch tester reach web by name

```bash
docker compose up
```

## Check Your Understanding

**Q1: How does `tester` know the IP address of `web`?**

<details><summary>Answer</summary>

It doesn't need to - Compose's automatic DNS resolves the service name `web` to the right container IP automatically.

</details>

**Q2: Do you need to write any --network flags in compose.yaml for this to work?**

<details><summary>Answer</summary>

No - Compose creates a default network for the whole project automatically, and every service joins it unless configured otherwise.

</details>

## Common Mistakes

- **Trying to use localhost to reach another service** - localhost inside a container refers to THAT container, not another service - use the service name instead.
- **Assuming you need Lab 1.10's manual `docker network create` step in Compose** - Compose does this automatically per project - manual network creation is a Module 1 concept for plain `docker run`, not needed here.

## Cleanup

```bash
docker compose down
cd .. && rm -rf net-demo
```
