# 2.7 Three-Tier App: Web + API + Database

## Concept Recap

This lab combines dependencies, networking, volumes, and environment variables into one realistic three-tier application.

## Objective

Build and run a web tier, an API tier, and a database tier together.

## Prerequisites

- Labs 2.1-2.6 complete

## Steps

### Step 1: Set up the project structure

```bash
mkdir three-tier && cd three-tier
mkdir api
cat > api/index.js <<'EOF'
const http = require('http');
http.createServer((req, res) => res.end(JSON.stringify({status: 'API is up', db: process.env.DB_HOST}))).listen(4000);
EOF
cat > api/Dockerfile <<'EOF'
FROM node:20-slim
WORKDIR /app
COPY index.js .
CMD ["node", "index.js"]
EOF
```

### Step 2: Write the full compose.yaml

```bash
cat > compose.yaml <<'EOF'
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: pw
    volumes:
      - db-data:/var/lib/postgresql/data
  api:
    build: ./api
    environment:
      DB_HOST: db
    depends_on:
      - db
  web:
    image: nginx
    ports:
      - "8080:80"
    depends_on:
      - api
volumes:
  db-data:
EOF
```

Note `build: ./api` - this tells Compose to BUILD an image from a Dockerfile instead of pulling one, unlike db and web which use pre-built images.

### Step 3: Bring the whole stack up

```bash
docker compose up -d --build
```

### Step 4: Verify each tier

```bash
docker compose ps
docker compose logs api
```

## Check Your Understanding

**Q1: What's the difference between `image:` and `build:` in a service definition?**

<details><summary>Answer</summary>

`image:` pulls a pre-built image from a registry; `build:` builds a new image from a local Dockerfile.

</details>

**Q2: Why does `web` depend on `api`, and `api` depend on `db`, rather than `web` depending on both directly?**

<details><summary>Answer</summary>

It reflects the real dependency chain - web talks to api, api talks to db - keeping the graph accurate and each service only aware of what it actually needs.

</details>

## Common Mistakes

- **Using image: for a service that needs a custom Dockerfile** - You need `build:` (pointing at the directory containing the Dockerfile) to build a custom image instead.
- **Forgetting --build after changing app source code** - `docker compose up -d` alone won't rebuild an image whose source changed - add `--build` explicitly.
