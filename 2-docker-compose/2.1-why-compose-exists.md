# 2.1 Why Compose Exists

## Concept Recap

Real apps are rarely one container - a typical app has a web server, an API, and a database, each needing its own network, volumes, and startup order. Running each with separate `docker run` commands is tedious and error-prone. Docker Compose lets you describe your ENTIRE multi-container app in one YAML file and bring it all up (or down) with a single command.

## Objective

Understand the problem Compose solves before writing any YAML.

## Prerequisites

- Module 1 complete

## Steps

### Step 1: See the problem firsthand

```bash
docker run -d --name manual-web --network manual-net -p 8080:80 nginx
docker network create manual-net 2>/dev/null || true
docker run -d --name manual-db --network manual-net -e POSTGRES_PASSWORD=pw postgres:16
```

Notice how many separate commands and manual network setup this took for just 2 containers - imagine 5.

### Step 2: Clean up the manual version

```bash
docker rm -f manual-web manual-db
docker network rm manual-net
```

## Check Your Understanding

**Q1: What problem does Compose primarily solve?**

<details><summary>Answer</summary>

Manually orchestrating multiple related containers (networks, volumes, startup order, environment) via many separate commands.

</details>

**Q2: Does Compose replace Docker itself?**

<details><summary>Answer</summary>

No - Compose is a tool that generates and manages the equivalent `docker` commands for you from a YAML description; Docker itself still runs the containers.

</details>

## Common Mistakes

- **Thinking Compose is a totally different technology from Docker** - It's a convenience layer on top of the same Docker engine and concepts you already learned in Module 1.
