# 2.6 Environment Files and Variable Substitution

## Concept Recap

Compose can read a `.env` file automatically and substitute `${VARIABLE}` references anywhere in compose.yaml - not just as environment variables passed to containers, but in the YAML structure itself (like port numbers).

## Objective

Externalize a port number and a password into a .env file.

## Prerequisites

- Lab 1.5 complete
- Lab 2.2 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Create the .env file

```bash
mkdir env-demo && cd env-demo
cat > .env <<'EOF'
WEB_PORT=8080
DB_PASSWORD=supersecret
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `.env` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `.env`).
2. Paste this content and save (`Ctrl+S`):

```
WEB_PORT=8080
DB_PASSWORD=supersecret
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 2: Reference variables in compose.yaml

```bash
cat > compose.yaml <<'EOF'
services:
  web:
    image: nginx
    ports:
      - "${WEB_PORT}:80"
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `compose.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `compose.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
services:
  web:
    image: nginx
    ports:
      - "${WEB_PORT}:80"
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 3: Bring it up and verify the substitution happened

```bash
docker compose up -d
docker compose config
```

`docker compose config` shows the fully-resolved YAML with variables substituted in - a great way to debug.

## Check Your Understanding

**Q1: Does Compose read .env automatically, or do you need a flag?**

<details><summary>Answer</summary>

Automatically, as long as it's named exactly `.env` and sits in the same directory you run `docker compose` from.

</details>

**Q2: What command shows you the fully-resolved YAML after variable substitution?**

<details><summary>Answer</summary>

`docker compose config`.

</details>

**Q3: Is it safe to commit a .env file with real production passwords to git?**

<details><summary>Answer</summary>

No - same rule as Lab 1.5: keep secrets out of version control.

</details>

## Common Mistakes

- **Naming the file env.txt or similar instead of exactly .env** - Compose only auto-loads a file literally named `.env` - anything else needs an explicit `--env-file` flag.
- **Not realizing docker compose config is a debugging tool** - Use it whenever a substitution isn't behaving as expected - it shows you exactly what Compose resolved.
