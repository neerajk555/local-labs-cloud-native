# 2.3 Service Dependencies and Startup Order

## Concept Recap

Compose starts services in the order you'd expect based on `depends_on`, but this only waits for the container to START, not for the app INSIDE it to be ready - a very common beginner trap.

## Objective

Use depends_on and understand its real limitation.

## Prerequisites

- Lab 2.2 complete

## Steps

### Step 1: Set up a service that depends on another

```bash
mkdir depends-demo && cd depends-demo
cat > compose.yaml <<'EOF'
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: pw
  app:
    image: alpine
    command: sh -c "echo 'app starting, db container exists but may not be ready yet' && sleep 30"
    depends_on:
      - db
EOF
```

### Step 2: Bring it up and watch the order

```bash
docker compose up
```


## Try It Yourself

**Exercise 1:** Look up (don't implement yet) what `depends_on` with a `condition: service_healthy` does differently from plain `depends_on`.

<details><summary>Hint (try first without peeking)</summary>

It waits for the dependency's HEALTH CHECK to pass, not just for the container to start - this is the real fix for 'db not ready yet' bugs.

</details>

## Check Your Understanding

**Q1: Does depends_on guarantee the database is ready to accept connections before the app starts?**

<details><summary>Answer</summary>

No - it only guarantees the db CONTAINER has started, not that Postgres inside it has finished initializing and is accepting connections.

</details>

**Q2: What's the actual fix for apps that crash because the database isn't ready yet?**

<details><summary>Answer</summary>

Use `depends_on` with `condition: service_healthy` (requires the db service to define a health check), or have the app itself retry its connection with backoff.

</details>

## Common Mistakes

- **Assuming depends_on solves all startup-order race conditions** - It only sequences container starts, not app-level readiness - this causes flaky 'first run fails' bugs.
- **Not adding retry logic in the app itself** - Even with health-check-based depends_on, well-written apps should still retry transient connection failures.
