# 2.2 Your First compose.yaml, Annotated

## Concept Recap

A compose.yaml file lists 'services' (what you'd normally run with `docker run`), each with an image, ports, and other options - directly mapping to flags you already know.

## Objective

Write and run your first compose.yaml.

## Prerequisites

- Lab 2.1 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Write the file

```bash
mkdir compose-demo && cd compose-demo
cat > compose.yaml <<'EOF'
services:
  web:
    image: nginx
    ports:
      - "8080:80"
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `compose.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `compose.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
services:
  web:
    image: nginx
    ports:
      - "8080:80"
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

Compare this to `docker run -d -p 8080:80 nginx` - `ports:` maps directly to `-p`.

### Step 2: Bring it up

```bash
docker compose up -d
```

### Step 3: See what Compose actually created

```bash
docker compose ps
docker ps
```

### Step 4: Bring it down

```bash
docker compose down
```

## Check Your Understanding

**Q1: What command brings a compose.yaml's services up?**

<details><summary>Answer</summary>

`docker compose up -d` (the `-d` runs them in the background, same meaning as with `docker run`).

</details>

**Q2: What command tears everything down?**

<details><summary>Answer</summary>

`docker compose down` - stops and removes all containers/networks Compose created for this project.

</details>

**Q3: In compose.yaml, what does the `ports:` list map to in plain `docker run` terms?**

<details><summary>Answer</summary>

The `-p hostPort:containerPort` flag.

</details>

## Common Mistakes

- **Forgetting -d and wondering why the terminal seems stuck** - Without -d, Compose runs in the foreground, streaming logs and blocking your terminal - press Ctrl+C or use -d.
- **Running docker compose up from the wrong directory** - Compose looks for `compose.yaml` (or `docker-compose.yml`) in your current directory by default.

## Cleanup

