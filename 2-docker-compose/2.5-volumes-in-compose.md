# 2.5 Volumes in Compose

## Concept Recap

Both bind mounts and named volumes (Lab 1.4) work in Compose too, expressed in the `volumes:` section of a service.

## Objective

Persist database data across a `docker compose down` and `up` cycle using a named volume.

## Prerequisites

- Lab 1.4 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Define a service with a named volume

```bash
mkdir vol-demo && cd vol-demo
cat > compose.yaml <<'EOF'
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: pw
    volumes:
      - db-data:/var/lib/postgresql/data
volumes:
  db-data:
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `compose.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `compose.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: pw
    volumes:
      - db-data:/var/lib/postgresql/data
volumes:
  db-data:
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

Note the top-level `volumes:` key declaring `db-data` - this is required for named volumes in Compose.

### Step 2: Bring it up, create some data conceptually, then tear down and recreate

```bash
docker compose up -d
sleep 5
docker compose down
docker compose up -d
docker volume ls | grep db-data
```

The volume persists across `down`/`up` because `down` doesn't remove volumes by default.

### Step 3: See what -v does differently

```bash
docker compose down -v
```

Adding -v to `down` DOES remove the named volumes - use this deliberately, not by habit.

## Check Your Understanding

**Q1: Does `docker compose down` delete named volumes by default?**

<details><summary>Answer</summary>

No - only `docker compose down -v` does. This is a deliberate safety default so you don't accidentally lose data.

</details>

**Q2: Where must you declare a named volume besides inside the service's volumes: list?**

<details><summary>Answer</summary>

In the top-level `volumes:` key at the bottom of the file - this declares it as a project-level resource.

</details>

## Common Mistakes

- **Habitually adding -v to docker compose down** - This destroys your data volumes - only use it when you actually want a clean slate.
- **Forgetting the top-level volumes: declaration** - Compose will error if you reference a named volume in a service without declaring it at the top level too.

## Cleanup

```bash
docker compose down -v
cd .. && rm -rf vol-demo
```
