# 2.9 Compose Profiles (Dev vs. Prod-Like Configs)

## Concept Recap

Profiles let you tag services as optional, so the same compose.yaml can run a minimal set of services by default, and extra ones (like a debugging tool) only when you explicitly ask for them.

## Objective

Use profiles to make a debug/admin service optional.

## Prerequisites

- Lab 2.2 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Define a default service and a profile-gated one

```bash
mkdir profile-demo && cd profile-demo
cat > compose.yaml <<'EOF'
services:
  web:
    image: nginx
  adminer:
    image: adminer
    ports:
      - "8081:8080"
    profiles:
      - debug
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `compose.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `compose.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
services:
  web:
    image: nginx
  adminer:
    image: adminer
    ports:
      - "8081:8080"
    profiles:
      - debug
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 2: Bring it up normally

```bash
docker compose up -d
docker compose ps
```

Only `web` starts - `adminer` is skipped because it's gated behind the 'debug' profile.

### Step 3: Bring it up WITH the debug profile

```bash
docker compose --profile debug up -d
docker compose ps
```

Now both start.

## Check Your Understanding

**Q1: Do profile-gated services start with a plain `docker compose up -d`?**

<details><summary>Answer</summary>

No - only services with NO profiles listed start by default; profile-gated ones need an explicit `--profile <name>` flag.

</details>

**Q2: Can a service belong to more than one profile?**

<details><summary>Answer</summary>

Yes - `profiles:` accepts a list, and the service starts if ANY of its listed profiles is requested.

</details>

## Common Mistakes

- **Forgetting --profile and wondering why a service never starts** - Check if it has a `profiles:` key - if so, it needs to be explicitly requested.
- **Using profiles for things that should always run** - Only gate genuinely optional services (debugging tools, seed-data jobs) - core services shouldn't need a profile flag to start.

## Cleanup

```bash
docker compose --profile debug down
cd .. && rm -rf profile-demo
```
