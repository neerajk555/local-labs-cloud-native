# 2.8 Scaling and Basic Load Balancing

## Concept Recap

Compose can run multiple identical replicas of a service. Combined with a simple load balancer in front, this is a miniature version of what Kubernetes does at much larger scale (Module 4+).

## Objective

Scale a service to multiple replicas and observe requests being distributed.

## Prerequisites

- Lab 2.7 complete
- (Optional but recommended) VS Code open on this project's folder — see `../USING-VSCODE.md` if you haven't set this up yet

## Steps

### Step 1: Set up an app that identifies itself

```bash
mkdir scale-demo && cd scale-demo
cat > index.js <<'EOF'
const http = require('http');
const os = require('os');
http.createServer((req, res) => res.end('Served by: ' + os.hostname())).listen(3000);
EOF
cat > Dockerfile <<'EOF'
FROM node:20-slim
WORKDIR /app
COPY index.js .
CMD ["node", "index.js"]
EOF
```

### Step 2: Compose file with no fixed container name (required for scaling)

```bash
cat > compose.yaml <<'EOF'
services:
  web:
    build: .
EOF
```

**Using VS Code instead of the heredoc above:**

1. In VS Code's Explorer panel, create a new file named `compose.yaml` in your current lab folder (right-click the folder → New File, or `Ctrl+N` then save as `compose.yaml`).
2. Paste this content and save (`Ctrl+S`):

```yaml
services:
  web:
    build: .
```

Any remaining commands in this step (the ones without a `cat > ... <<EOF` block) still need to run in a terminal — use VS Code's built-in one via **Terminal → New Terminal** (or `` Ctrl+` ``) so you don't need to switch windows.

### Step 3: Scale to 3 replicas

```bash
docker compose up -d --build --scale web=3
```

### Step 4: See all 3 containers

```bash
docker compose ps
```

### Step 5: Hit each one directly to confirm they're distinct

```bash
docker compose exec web hostname
```

Compose picks one arbitrarily for `exec` - use `docker ps` to get each container's specific name and `docker exec <name> hostname` to check each individually.

## Check Your Understanding

**Q1: Can you give a scaled service a fixed container_name?**

<details><summary>Answer</summary>

No - `container_name` conflicts with scaling to multiple replicas, since names must be unique; leave it unset for scaled services.

</details>

**Q2: How does Docker's embedded DNS handle a service name that has multiple replicas?**

<details><summary>Answer</summary>

It returns multiple IP addresses for that one name, and clients (or a load balancer) typically round-robin between them.

</details>

## Common Mistakes

- **Setting container_name on a service you plan to scale** - This causes an immediate conflict error on the second replica - remove container_name from scaled services.
- **Expecting docker compose exec to let you target a specific replica by number** - It doesn't distinguish replicas - use `docker ps` to find exact container names, then `docker exec <exact-name>`.
